# Jev × Decision：完整 Tetris V8 接入

2026-10-18。此次只接通 Jev 图像协议并开放混合对战，不修改冻结 V8 策略、目标目录、原生动作、时钟、计分或请求预算，不启动 GEPA，也不修改参考项目。

## 原因与改动

之前禁用 Jev 的原因是 Arena 只实现了 System One 的图片传输格式，并非 Jev 缺少视觉能力。[OpenRouter 多模态 Decisions 文档](https://openrouter.ai/docs/guides/community/multimodal-decisions)明确规定 `state` 可含文本和 `image_url`；Jev 不接受顶层 `images`。[TypeSafe Jev 1.14 公告](https://typesafe.ai/blog/jev-1-14)说明 1.14 及 1.13 的图片支持仍属实验能力。

- 同一个 `supportsDecisionImages` 检查用于模型选择器、Web 创建、Runner 创建和最终传输。OpenRouter、自定义兼容接口、BambooNode Decisions 下的精确请求型号 `typesafe/jev-1.13`、`typesafe/jev-1.14` 可以选择 V8。未知型号仍拒绝；没有仅凭 provider 放开所有模型。
- Jev 请求使用 `state: [JSON.stringify(完整结构化观察), {type: "image_url", image_url: {url: PNG数据URL}}]`。System One 保持顶层 `images`。目标及按键请求均带各自本次观察的图像；没有纯文本降级、自动寻路、代选、提前落点或付费重试。
- 当前 PNG 为 384×576，满足 Jev 尺寸限制；完整字节保留。无图请求保持原格式。事件只记录哈希、宽高，不存图片或原始请求。
- 两侧分别保持目标、方块作用域、历史、预算和一个在途请求。仍以真实时间运行。新局默认 V8；旧局和沿用配置保持原版本。Clone 用观看者自己的凭证，并在冻结原模型后检查视觉能力及 Bamboo 访问。
- Arcade 配置强制 `never`；System One 明确发送 `think_mode: never`。Jev 不接收不存在的 System One 思考参数；未返回的思考遥测保持“未返回”，不能伪造为 false。
