# V8 双 AI 默认启用与本地验证

日期：2026-10-18。本次按用户要求将新建俄罗斯方块默认切换为 `tetris-harness-v8-realtime-v1`，覆盖单 AI、人机和 AI 对决。旧方案保留为显式对照；已创建对局、历史回放和社区沿用配置保持原版本。本次只验证双 AI 接入，不修改冻结 V8 策略、原生规则、速度或计分，也不改写此前独立配对实验的结论。

## 发现与修改

用户截图中的创建页选中的是 `tetris-harness-baseline-v1`。实际查看私有房间 `arcade-7b2438bf-056a-4281-bd98-8e07f96c3053`，确认它也是 baseline：本地 StartLux 与 Jev 均 0 分，并多次选择硬降。不能把该局当成 V8 双 AI 失败案例。

V8 执行器原本就按每个 Run 工作，不限定单 AI。本次将表单、Web 创建服务和 Runner 创建入口的缺省值同时切换到 V8。模型兼容性检查使用归一化后的版本，不能通过省略版本让 Jev 静默进入旧方案。房间及创建页明确标出双方共同使用 V8；每侧仍有独立目标、最近动作、请求和预算。历史缺字段依然解释为 baseline，沿用旧回放也不会被重标。

本次历史验证时，Arena 的图片适配器只实现了 System One，因此 UI 将 Jev / OpenRouter Decisions 限制在显式 baseline；这是当时 Arena 的接入限制，并非 Jev 不支持图片。之后已按官方多模态协议补齐 Jev 1.13/1.14，见[单独的 Jev 接入验证](jev-integration.md)。下述原始实测使用的仍是两侧 StartLux，数字与实验范围不变。

## 真实双 AI 冒烟验证

从已登录用户的创建页面创建，两侧均选择既有的 `new-api · StartLux 27B（本地）`，没有读取或复制模型 Key。固定种子 `v8-duel-smoke-20261018`；保持 10×20、60 Hz、120 秒、每侧原有调用预算与 500ms 最小启动间隔。额外设置本次验证总调用上限 160，156 次时结束以预留并发余量；实际仅 58 次，没有触及该阈值。没有重试、暂停、降速或自动发布。

对局：`arcade-e1655c7b-fec1-44d5-a40d-f6a473e8fef9`，06:29:39–06:31:45 UTC（包含终局后在途请求收尾）。请求和实际返回模型均为 `startlux-decision-27b-autothink`。

双方按平台规则判平，未消行。不能把接入成功说成得分改善，也不能与此前不同种子、不同并发条件的单 AI 分数构成公平新旧对照。

所有 15 次丢弃都有可重放的时序证据：左侧 6、右侧 7 次按键在返回前已换块，另各 1 次目标在游戏到达 120 秒后返回。例如左侧 `hard-drop:100` 观察 tick 792、结算 tick 1002、无应用 tick；原生重放确认方块由 #1 变为 #2。右侧同类动作观察 tick 859、结算 tick 1070、无应用 tick，亦由 #1 换成 #2。这些动作未被套用到下一块。

现场观察到最多两个同时在途请求。两侧分别重放，共 324 个检查点及最终成绩完全一致；每个执行输入与模型返回一致，目标事件从未直接执行按键。双请求下的响应延迟确实给实时控制留下更少机会；仅凭本次结果无法将延迟进一步归因于模型排队、推理、缓存或网络，也不能认定它是零分的唯一原因。

私有本地证据保存在忽略目录 `artifacts/tetris-v8-duel/`，只保存白名单决策指标、时间与有限失败窗口；不保存原始请求、图像内容、思考、模型 Key 或完整私有回放。临时本站会话文件在验证结束后删除。

## 复现与回滚

打开 `/zh/arcade/new?game=tetris`，选择 AI 对 AI，左右各选支持图片的 System One 模型。保持默认 V8，输入上述种子并开始；可以在两侧看到独立的目标/按键阶段。相同模型和种子不保证相同输出及响应时序，本局结果不能视为确定性能力保证。

显式选择“原有方案（对照）”即可为下一局回滚。进行正式新旧能力比较时应另建相同种子、预算与并发条件的交错实验，不追加挑选有利局面到本次冒烟结果。

新增 DO 测试覆盖两侧不同响应顺序、独立目标和历史、每侧最多一请求/总计两请求、完整 PNG 与 `think_mode=never`、同一模型配置的独立调用预算；旧持久局恢复和沿用版本测试继续保留。

本次验证通过：`pnpm test`（611 项）、`pnpm test:runner`（155 项、实际本地 workerd + 模拟供应商）、`pnpm typecheck`、`pnpm build`、`pnpm build:cloudflare`、浏览器创建及双 AI 终局显示、真实 58 次模型调用与 324 检查点回放复核。生产环境没有部署。
